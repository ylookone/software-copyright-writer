# 软件著作权材料撰写 Skill

> 将真实软件项目整理为有证据支撑、可审核、可继续修改的中国计算机软件著作权登记材料。

已经有可以运行的项目，却不知道怎样把代码、配置和软件界面整理成规范的软著设计说明书？

需要严格匹配样例的封面、自动目录、硬件配置表、总体流程图、页眉、页码和可编辑 Word 文档？

**本 Skill 以 `SKILL.md` 和配套规则文件组织完整流程：检查项目、建立事实依据、撰写材料、同步生成 Markdown 与 DOCX，并完成内容一致性和页面视觉检查。**

## 功能特性

| 能力 | 说明 |
| --- | --- |
| 项目检查 | 读取源码、依赖文件、配置、路由、界面、数据库结构、日志、截图和已有文档。 |
| 事实控制 | 在撰写前区分已核实、用户确认和待确认信息。 |
| 设计说明书 | 按固定封面和章节结构生成中文软件设计说明书。 |
| Markdown 与 Word | 生成内容同步的中文 `.md` 和 `.docx`，保持章节、表格、图片和题注一致。 |
| 运行环境 | 根据本地项目填写软硬件要求 |
| 一致性核查 | 检查名称、版本、功能、图表、截图、环境、标题层级和页面版式。 |
| 迭代完善 | 将真实产物中发现的共性问题转化为撰写规则和对应的质量检查项。 |

> **图片说明：** Skill 可以组织图片位置并生成文档结构，但不会伪造软件界面截图。需要展示界面或运行结果时，应加入真实项目截图。

## 安装

整个仓库构成一个完整 Skill。安装时应确保 `SKILL.md` 位于 Skill 目录根级。

### Codex

将完整仓库复制或克隆到 Codex skills 目录：

```bash
git clone <仓库地址> ~/.codex/skills/software-copyright-writer-en
```

如果没有立即识别到 Skill，请重新加载 Agent 环境。可以使用以下名称显式调用：

```text
$software-copyright-writer-en
```

### 其他 Agent

核心规则均为 Markdown 文件，不限于 OpenAI 模型。

如果目标 Agent 支持 `SKILL.md` 或 Agent Skills，可以将整个仓库复制到该产品规定的 skills 目录。如果不支持自动发现，可以先要求 Agent 阅读 `SKILL.md`，再按其中的指引读取 `references/` 下的规则文件。

`agents/openai.yaml` 只包含 OpenAI/Codex 的可选展示信息，其他 Agent 可以忽略。

目标 Agent 还需要具备对应的项目文件读取、DOCX 生成、Word 字段更新、文档渲染和页面视觉检查能力。

## 使用方法

使用自然语言说明需求，并提供项目路径或仓库。常见触发方式包括：

- 撰写软件著作权登记材料；
- 生成中文软件设计说明书；
- 编写软著说明书或操作手册；
- 整理源程序鉴别材料；
- 核查整套软著材料；
- 修改已有软著文档。

示例提示词：

```text
使用 $software-copyright-writer-en 分析这个项目，生成中文软件设计说明书，
并同时交付内容一致的 Markdown 和 DOCX 文件。只使用仓库和现有材料能够
证明的事实，无法确认的登记字段放在提交文档之外单独列出。
```

建议同时提供以下材料：

- 真实项目仓库；
- README 和依赖文件；
- 配置文件及数据库定义；
- 真实软件界面截图；
- 已有说明书或登记材料草稿；
- 已确认的软件名称、版本号和申请人；
- 部署记录或运行环境信息。

Skill 应先完成所有有证据支持的工作，再询问无法从现有材料中确定的信息。

## 文档规则

当前设计说明书采用以下固定要求：

1. **封面**：按照规定的顺序和字号，仅放置软件名称、版本号、`设计说明书`和申请人。
2. **目录**：生成并更新两级自动目录，统一使用 11 磅文字、分级缩进、点引导线和动态页码。
3. **第一章**：只设置 `1.系统概述`，不设置 `1.1` 等小标题。正文按照背景、问题、改进方法和实际效果展开，并在效果部分说明完整软件系统。
4. **第二章**：固定为 `2.软件开发环境`，只填写已经核实的开发信息。
5. **第三章**：固定为 `3.软件运行环境`，包含 `3.1硬件环境要求`、两列五行硬件表和 `3.2软件环境配置`。
6. **第四章**：固定为 `4.软件实现方法`；第 4.1 节首先说明完整流程，图1固定为“软件总体流程图”。
7. **后续章节**：根据真实项目安排功能操作、数据处理、结果保存和异常处理等内容。
8. **不设置待完善章节**：`待完善信息`不能作为编号章节、正文小节或目录条目。
9. **页眉**：软件全称和版本号位于正文区域的几何中心，动态页码位于最右侧；封面和目录页眉为空。
10. **页脚**：所有页脚保持空白。
11. **交付检查**：生成 DOCX 后逐页渲染，检查封面、目录、页眉、表格、图片、分页和文字显示。

完整实现要求见 [`references/document-blueprints.md`](references/document-blueprints.md)。
